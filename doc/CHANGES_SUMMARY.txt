BMS CONFIGURATION WITH ID & NAME SUPPORT - IMPLEMENTATION SUMMARY

OVERVIEW:
Implemented three-rule system for BMS device identification with names and IDs

RULES IMPLEMENTED:
1. Auto-Scan Mode: ID auto-generated from MAC, name omitted
2. Config Mode: ID from config or auto-generated, name optional
3. Optional Fields: No null values, fields omitted if empty

static std::string extractIdFromMac(const std::string& mac)

================================================================================
ID GENERATION RULES
================================================================================

Format: Last 4 hex characters of MAC address (excluding colons)

Examples:
  02:11:22:33:44:55 → 4455
  02:aa:bb:cc:dd:ee → ddee
  02:12:34:56:78:9a → 789a
  a1:b2:c3:d4:e5:f6 → e5f6

Auto-Generation:
  Triggered when id field is nullptr in config
  Always generated for auto-scan mode
  Max 65,536 unique IDs (16^4) - no collision risk with 8 devices

================================================================================
NAMING RULES
================================================================================

Format: Any string (max length depends on memory)
Recommended: 10-30 characters

Examples:
  "Battery-House"
  "Solar-Array"
  "Backup-UPS"
  "BMS-1"

Omission:
  When name field is nullptr in config → omitted from JSON
  Empty string → treated as no name, omitted from JSON
  Auto-scan mode → always omitted from JSON

================================================================================
KNOWN LIMITATIONS & NOTES
================================================================================

1. ID Collision: Minimal risk with last 4 MAC chars and max 8 devices
2. Name Length: Limited by stack/heap memory availability
3. MAC Format: Must be "XX:XX:XX:XX:XX:XX" (lowercase or uppercase, auto-converted)
4. Config Order: Devices processed in array order
5. Auto-Scan: Can be triggered multiple times per session
6. Device Update: Scans update both MAC RSSI and can reapply config
